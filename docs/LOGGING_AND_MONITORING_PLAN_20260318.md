# 日志与长期监控规划

## 目标

为了支持：

- PC 仿真
- MCU 板子长期运行
- 长时间问题定位
- 复盘和回放

日志必须从“零散 printf”升级为“结构化、分级、可持续记录”的体系。

## 当前问题

当前项目日志存在几个明显问题：

- 日志入口分散在 `printf` / `BSP_Printf`
- 缺少统一等级
- 缺少统一格式
- 缺少运行快照
- 缺少面向长期运行的落盘与轮转策略

## 推荐日志分层

### 实时日志

适合串口/J-Link RTT/PC stderr 输出：

- 启动阶段
- 模块初始化失败
- 协议解析异常
- 状态切换
- 关键保护动作

### 事件日志

适合 EEPROM 或文件持久化：

- 上电
- 睡眠
- 告警出现/恢复
- 保护动作
- 参数重置

### 周期快照

适合长期监控：

- 电压
- 电流
- 温度
- SOC
- MOS 状态
- 休眠状态
- 通讯统计
- 错误计数器

## 建议新增的日志字段

每条日志建议至少包含：

- level
- module
- event
- timestamp
- key fields

PC 端可以写成文本或 JSON Lines。  
MCU 端可以先用文本串口输出，再视空间情况决定是否做压缩事件记录。
