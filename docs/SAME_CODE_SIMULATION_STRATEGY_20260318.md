# 同码 PC 仿真策略

## 目标

你要的不是“另外写一套 PC 测试代码”，而是：

- 正式板子跑的业务代码尽量不分叉
- PC 端也跑同一份业务代码
- 只有硬件层被替换为 stub / fake / adapter
- 日志能力在 PC 和 MCU 两侧同时增强

这个方向是对的，也是后续最值得投入的方向。

## 当前现实

当前仓库还没有达到“同码仿真”结构。

主要原因：

- `main.h` 聚合了大量硬件相关头文件
- 业务层直接读写全局硬件状态
- 大量函数直接调用 GPIO / ADC / RTC / EEPROM / Flash / USART
- 启动、时钟、休眠、喂狗、中断逻辑与 MCU 强耦合

所以现在还不能把主工程直接搬到 PC 上运行。

## 需要改造成什么结构

目标结构建议拆成三层：

### 1. app_core

纯业务层，可被 MCU 和 PC 共用：

- 协议解析
- 数据适配
- 状态机
- 保护决策
- 调度逻辑

### 2. platform_api

统一平台接口层：

- 时间
- 延时
- 日志
- EEPROM
- Flash
- 串口收发
- GPIO 输入输出
- ADC/温度/电流采样快照
- reset/watchdog

### 3. platform_impl

两套实现：

- `platform_mcu`
- `platform_pc`

这样 PC 端与 MCU 端的区别只保留在 `platform_impl`。

## 推荐的落地顺序

1. 先统一日志入口
2. 再统一时间/延时接口
3. 再统一 EEPROM/Flash/串口/GPIO 的平台接口
4. 再把业务逻辑从全局变量和硬件寄存器调用里抽出来
5. 最后让 `main loop` 在 PC 和 MCU 复用

## 你现在应该怎么理解“同码仿真”

短期内：

- 先做到“协议层和业务规则同码”
- 硬件层用 PC stub 替代

中期：

- 让调度器、状态机和告警逻辑也能同码

长期：

- 让 MCU 与 PC 共享大部分 `app_core`
- PC 负责回放日志、喂入假数据、做长时间压力运行

## 结论

可以做，而且值得做。  
但当前仓库还需要一个“平台抽象化”的改造阶段，才能真正达到“除了硬件之外，PC 和板子跑同一套代码”。
